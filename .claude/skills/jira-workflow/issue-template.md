# Jira 이슈 작성 템플릿

> Jira 이슈의 제목·설명 **작성 형식**만 정의한다. 생성·수정 시점과 승인 절차는 같은 폴더의 `SKILL.md`(jira-workflow)를 따른다.

## 1. 적용 대상
- 신규 Jira 이슈 생성
- Sub-task 생성 (상위 이슈를 parent로 연결)
- 기존 이슈 설명 수정
- 작업 범위 변경에 따른 이슈 업데이트

기존 이슈를 수정할 때는 기존 내용을 일괄 삭제·재작성하지 않는다. 템플릿에 맞춰 누락된 섹션을 보완하고 변경된 부분만 고친다.

## 2. 템플릿
```markdown
## 배경 / 목적
- (작업이 필요한 이유)

## 목표 (To-be)
- (완료 후 기대 동작·결과)

## 작업 내용
- `경로/파일` 생성 | 수정 | 삭제

## 완료조건
- [ ] (검증 가능한 조건)
- [ ] Unity Editor에서 컴파일 오류 및 관련 Error / Warning 로그가 발생하지 않는다.

## 특이사항
- (해당 시에만 작성)
```

## 3. 작성 규칙

### 3.1 제목 (Title)
- 20자 이내로 작성한다.
- 상세 기술 키워드보다 **기능 단위**로 작성하고 불필요한 수식어를 뺀다.
- 이슈 키(`RSP-번호`)는 제목에 넣지 않는다.
- 예: `플레이어 이동 구현`, `몬스터 피격판정 구현`, `Weapon 베이스클래스 생성`

### 3.2 배경 / 목적 (필수)
- 이슈 생성 전 사용자에게 작업 배경과 목적을 확인한다.
- 현재 대화에서 사용자가 명확히 제공한 정보는 재사용할 수 있다. 근거가 없으면 반드시 질문한다.
- **배경과 목적을 확인할 수 없으면 이슈를 생성하지 않는다.** 추측으로 채우지 않는다.
- 리스트 형태의 간결한 문장으로, 작업이 필요한 이유를 명시한다.

```markdown
## 배경 / 목적
- 플레이어 피격 판정 시 데미지 수치와 공격 판정 데이터 동시 전달 필요
- `DamageInfo` 구조체를 전달하는 방식으로 피격 판정 개선
```

### 3.3 목표 (To-be)
- 작업 완료 후 예상 동작과 결과를 리스트로 작성한다.
- 검증 가능한 결과 중심으로 쓴다.

```markdown
## 목표 (To-be)
- 플레이어와 몬스터가 `IDamageable.TakeDamage(DamageInfo info)`를 통해 공격 판정을 처리
- `DamageInfo`가 공격 주체에서 피격 대상으로 전달
```

### 3.4 작업 내용
- 예상 변경사항을 **생성 / 수정 / 삭제**로 구분한다.
- 프로젝트 구조를 실제로 확인한 뒤 파일 경로를 쓴다. 확인하지 못한 경로는 `(예상)`을 붙인다.
- 새 콘텐츠 경로는 `unity-guidelines.md` 2장의 `Assets/` 구조를 따른다.

```markdown
## 작업 내용
- `Assets/Scripts/Interfaces/IDamageable.cs` 수정 (예상)
- `Assets/Scripts/Core/DamageInfo.cs` 생성 (예상)
- `Assets/Prefabs/Characters/PFB_Player.prefab` 수정 (예상)
```

### 3.5 완료조건
- 목표와 작업 내용에 대응하는 체크리스트로 작성한다.
- 실제로 검증할 수 있는 조건만 쓴다.
- Unity 개발 작업은 Editor 컴파일·Error/Warning 로그 확인 항목을 포함한다.
- 검증하지 않은 항목은 체크(`[x]`)하지 않는다.

```markdown
## 완료조건
- [ ] `IDamageable`을 통해 데미지 판정이 처리된다.
- [ ] `TakeDamage(DamageInfo info)`를 통해 데이터가 전달된다.
- [ ] 피격 대상에서 `DamageInfo` 정보가 정상 출력된다.
- [ ] Unity Editor에서 컴파일 오류 및 관련 Error / Warning 로그가 발생하지 않는다.
```

### 3.6 특이사항 (조건부)
다음에 해당할 때만 작성하고, 해당 사항이 없으면 섹션을 생략한다.
1. 선행 작업이 필요한 경우
2. 다른 Jira 이슈와 연관된 경우
3. 해결된 블로커 또는 관련 문제가 있는 경우

관련 이슈는 실제 조회한 이슈 키로 Jira 이슈 링크(issue link) 기능 또는 이슈 참조로 연결한다. 존재를 확인하지 않은 이슈 키를 쓰지 않는다.
