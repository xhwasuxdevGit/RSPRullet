# 기획서 → 포트폴리오 Google 문서 변환

## 1. 기준
- 기준 양식: [RSPRullet 게임 컨셉 기획서 (포트폴리오)](https://docs.google.com/document/d/1lC3-zZ-fL7MkuTD7gSIgSz4jUrFBvNuAVOnQZEteSI4/edit). 서식 값은 `style-spec.json`에 있다. **매번 기준 문서를 다시 분석하지 않는다.**
- **단락 앞뒤 간격 = 그 단락의 글자 크기**(사용자 지정). 고정 pt가 아니다: 문서 제목 23, 장 제목 19, 절 제목 15, 소제목·부제 13, 본문·목록 12, 표 안 글자 11(간격 미적용). 목차 항목·빈 줄(spacer)·구분선 단락은 0, 표 안은 적용하지 않는다. 글자 크기를 바꾸면 간격도 같이 바꾼다.
- 목차 제목은 "목차"만 쓴다(영문 표기 없음).
- **긴 항목 분리 규칙**: "항목명: 내용" 목록이 한 줄을 넘으면 항목명(굵게, 콜론 없음)만 그 항목에 남기고, 내용은 **한 단계 아래 하위 항목**으로 내린다. 한 줄 기준은 본문 폭 498pt·12pt 글자로 추정한다: 1단계 약 38자, 2단계 약 36자(한글 1, 영문·숫자 0.55, 공백 0.3으로 계산). 번호 목록의 하위 항목은 a, b 기호가 붙는다.
- **절 사이 빈 줄**: 한 장 안에서 절 제목(제목2)에서 다음 절 제목으로 넘어갈 때 앞에 빈 줄 한 줄을 둔다. 장의 첫 절과, 이미 빈 줄(표 뒤 빈 줄 포함)이 있는 곳에는 추가하지 않는다. **절 제목 바로 앞 빈 줄의 글자 크기는 절 제목 크기(15pt)로 고정**한다(앞뒤 간격은 0).
- **도식화**: 흐름(진행 순서·분기)이나 관계(구성 요소 간 연결)를 설명하는 절은 기준 문서처럼 도식을 넣는다. 원본에 머메이드 등 도식이 있던 곳이 1순위다. 만들기 전에 반드시 "5-1. 도식 작업 절차"의 도식화 브리핑(필요한 위치·이유·구성·대안 비교)으로 승인을 받는다.
- **마침표 단락 분리 규칙**: 한 단락에 문장이 여러 개면 마침표(". ") 뒤에서 일반 줄바꿈(Enter)으로 문장마다 단락을 나눈다. 본문은 그대로 새 단락, 목록 항목은 두 번째 문장부터 **글머리 기호 없이 항목 글자 위치에 맞춘 연속 단락**(들여쓰기 = 그 단계의 글자 시작 위치, 1단계 32.4pt, 2단계 64.8pt)으로 둔다. 쉼표에서는 줄바꿈하지 않는다. 제목·목차·표 안은 적용하지 않는다.
- **정렬**: 본문·목록·제목은 모두 왼쪽 정렬. 가운데 정렬은 표 머리행에만 쓴다. 정렬 요청은 셀 안 단락 범위로만 보내고, 표나 행 범위로 보내지 않는다(표 바로 앞 단락까지 함께 바뀐다).
- 사용자가 다른 템플릿을 지정할 때만 그 문서를 docx로 내보내 XML에서 값을 뽑아 `style-spec.json` 사본을 만든다. `read_doc`은 표 테두리·셀 여백·표 스타일을 돌려주지 않으므로 서식 분석에 쓰지 않는다.
- Google 커넥터 사용 규칙은 `google-workspace` 스킬(references/docs.md)을 먼저 읽고 따른다.

## 2. 사전 확인
- Google Drive·Google Docs 커넥터 연결 확인. 없으면 연결을 요청하고 시작하지 않는다.
- 원본: `RSPRulletDocs` 스페이스의 해당 기획서. 세부 기획서 목록을 적을 때는 실제로 조회한 문서만 적는다.

## 3. 내용 정제
- 뺀다: "구현 키워드", 미정·확정 예정 등 작업 상태 표시, 검토 중인 후보안, 내부 작업 메모.
- 올린다: 기획 의도와 설계 원칙. 각 절은 "기획 의도:" 항목으로 시작한다.
- 흐름도(머메이드)는 "[A] ➔ [B]" 텍스트로 바꾼다. 원본에 없는 값은 만들지 않는다.
- 장 구성은 기준 문서를 따른다: 목차 → 1 프로젝트 개요 → 2 시스템 기획 → 3 컨텐츠 기획 → 4 프로젝트 운영. 제목은 "📝 1. 프로젝트 개요"처럼 이모지 + 번호, 이모지는 겹치지 않게.

## 4. 작업 순서 (토큰 절약형)
1. **원고 작성**: `base.html`의 `<style>` 머리를 그대로 쓰고 본문만 작성한다(아래 5장 규칙). **로컬 파일로 저장하지 않고** Drive `create_file`(`contentMimeType: text/html`)의 `textContent`에 바로 한 번만 쓴다(같은 원고를 두 번 쓰면 토큰이 두 배). 고칠 내용은 문서에서 직접 고친다.
   - 업로드 전에 **도식화 브리핑**(5-1장 0번)을 하고 승인받는다. 승인된 위치에는 원고에 `[도식 삽입: 파일명]` 표시 단락을 미리 넣어 둔다.
2. **보정**: `read_doc` 결과(파일로 저장됨)에 `python postfix.py <저장 파일>`을 돌려 나온 `requests`·`writeControl`을 `update_doc` 한 번에 보낸다. 출력이 크면 스크립트 출력을 2개로 나눠 보내되, 두 번째 전에는 다시 읽어 리비전을 갱신한다(스타일 요청만 있는 묶음은 위치가 바뀌지 않는다. 삽입 요청은 항상 마지막 묶음에).
3. **검증**: Drive `download_file_content`로 docx를 내보내 `python -I check_format.py <docx>`를 돌린다. "OK"면 끝, ✗ 항목만 그 범위를 고친다. PDF 내보내기는 페이지 없음 문서에서 실패하므로 쓰지 않는다.
4. **보고**: 링크(같은 문서면 링크 유지 명시), 정제 내용, 검증 결과, 미검증 항목(화면 모양은 직접 못 봄)을 적는다.

- 금지: 서식을 수백 건의 수정 요청으로 덧입히기, 같은 요청 JSON을 두 번 이상 읽기(`update_doc`에 넘기려면 한 번은 읽어야 한다. 다시 만들면 바뀐 부분만 요약 출력해 확인), 큰 `read_doc` 결과를 대화로 읽기(항상 스크립트로 요약).
- 보정 뒤 `check_format.py`에 남는 항목(표 굵게, 절 앞 빈 줄 크기, 본문 간격, 마침표 분리)은 `python postfix.py <저장 파일> --extra-only`로 그 부분만 다시 만들어 보낸다.
- **굵게 복원(예외용)**: `<style>`에 글꼴 규칙을 넣으면 글자 굵기가 400으로 고정되어 `<b>`가 모두 사라진다(2026-11-25 시험). 글꼴 규칙을 빼면 본문·제목·표의 `<b>`가 유지되므로 평소에는 쓰지 않는다. 그래도 사라졌을 때만 원고를 파일로 저장해 `--bold-src <원고.html>`을 붙이면 원고의 `<b>` 구절을 문서 글자(표 포함)에서 차례로 찾아 굵게 요청을 만든다. 못 찾은 구절은 stderr로 나온다. 출력은 같은 서식 범위를 합쳐(굵게 간격 3자 이하, 이어진 같은 단락 스타일) 요청 수를 줄인다.

## 5. HTML 작성 규칙 (2026-11-25 시험 결과 기준)
| 서식 | HTML에서 | 비고 |
|---|---|---|
| 굵게 | `<b>` 또는 `<strong>` | 유지된다. 단 `<style>`에 `font-family`를 넣으면 모두 사라진다. class·`<style>`의 font-weight는 쓰지 않는다 |
| 글꼴 | **`<style>`에 넣지 않는다** | 굵게가 사라지므로 글꼴은 보정에서 문서 전체에 한 번 적용 |
| 본문 | `<p>` (앞뒤 = 글자 크기, 줄간격 150%(1.5)) | 문서 첫 단락들은 간격이 0으로 들어가므로 보정에서 맞춘다 |
| 소제목 | `<p class="lab"><b>핵심 목표</b></p>` | 13pt 굵게 |
| 빈 줄 | `<p class="sp"><br></p>` | 소제목 앞, 장 끝(구분선 앞) |
| 목록 | `<ul><li>` (1단계 32.4/16.2pt, 단계마다 32.4pt, 앞뒤 12pt, 글자 12pt) | 2단계 이하 들여쓰기는 보정에서 처리 |
| 목차 | `<h1>목차</h1>` + `<li class="toc">` | 목차 항목은 앞뒤 0pt |
| 항목명 (한 줄 이내) | `<li><b>항목명:</b> 설명</li>` | |
| 항목명 (한 줄 초과) | `<li><b>항목명</b><ul><li>설명</li></ul></li>` | 내용은 하위 항목. 하위 목록 들여쓰기는 보정에서 처리 |
| 문장 분리 (본문) | 문장마다 `<p>` | |
| 문장 분리 (목록) | `<li>첫 문장.</li>` 다음에 `<p class="cont" style="margin-left:32.4pt">둘째 문장.</p>` | `<p>`가 끼면 번호 목록 번호가 다시 1부터 시작할 수 있으므로, 번호 목록은 `check_format.py` 확인 뒤 보정한다. 보정: `. `의 공백을 `\n`으로 바꾸고 새 단락에 `deleteParagraphBullets` + 들여쓰기(첫 줄·전체 = 그 단계 글자 위치) |
| 구분선 | `<hr>` 다음에 `<h1>` | 제목에 붙어 들어가므로 보정에서 분리 |
| 표 | `<table>` 머리행 `<tr class="h">`, 마지막 행 `<tr class="z">`, 첫 열 `<td class="l">`, 끝 열 `<td class="r">` | 테두리·음영·여백·세로정렬은 `<style>`로 살아남음. 머리행·첫 열은 `<b>`로 감싼다(보정에서도 굵게를 한 번 더 확인). 열 너비와 셀 안 단락(줄간격 1.0, 앞뒤 0. 줄간격이 크면 세로 가운데 정렬이 어긋나 보이고, 변환 때 셀 여백이 단락 앞뒤 6pt로도 들어가 겹친다)은 보정에서 설정. 문서 전체 줄간격을 바꿀 때 표 안은 제외한다 |
| 문서 제목 | 첫 `<h1>` | 보정에서 TITLE로 바꾼다 |

## 5-1. 도식 작업 절차 (토큰 절약형, 사용자 삽입)
0. **도식화 브리핑 (승인 전 작성 금지)**: 원고를 정제한 뒤, 도식을 만들기 전에 아래 형식으로 브리핑하고 사용자 승인을 받는다.
   ```text
   ## 도식화 브리핑
   | 위치(장·절) | 도식이 필요한 이유 | 구성 내용(노드·흐름) | 도식 종류 |
   | 예: 2.1 라운드 진행 | 패배 시 재도전 분기가 글로는 따라가기 어려움 | 시작→1R→2R→3R→클리어, 각 라운드 패배→응급약 복용 | 흐름도(LR) |
   **대안 비교** 위치·구성·방식(이미지 도식 / 표 도식 / 텍스트 흐름 유지)에 대안이 있으면 장단점 표로 비교하고 권장안을 밝힌다. 대안이 없으면 "해당 없음: 이유".
   진행할까요?
   ```
   - 후보 기준: 원본에 도식이 있던 곳, 진행 순서·분기·순환이 있는 절, 구성 요소 간 관계를 설명하는 절.
   - 승인된 위치·구성대로만 만든다. 사용자가 빼거나 바꾼 항목은 반영하고 다시 묻지 않는다.
1. 머메이드 원문(`.mmd`)을 `Docs/Portfolio/diagrams/`에 `장-절_이름.mmd`로 쓴다. 직선 흐름은 `flowchart LR`, 주고받는 순서는 `sequenceDiagram`(자기 동작은 화살표 대신 `Note over`로 써야 글자가 세로선과 겹치지 않는다), 분기·되돌아가기는 자기 반복 화살표 대신 별도 노드로 모은다(계단식 배치 방지).
2. 로컬에서 PNG로 변환한다. 설치된 Chrome을 쓰므로 브라우저 내려받기는 없다:
   `npx -y @mermaid-js/mermaid-cli@11.4.2 -i X.mmd -o X.png -c <skill>/mermaid-config.json -p <skill>/puppeteer.json -b white -s 2 -w 1000`
   - `mermaid-config.json`: 문서 색(#F8FAFC 상자, #94A3B8 테두리, #1E293B 글자)과 Noto Sans KR. 한글은 로컬 글꼴이라 깨지지 않는다.
3. PNG를 Read로 열어 확인한다(겹침·잘림·이상한 줄바꿈). 고칠 때는 `.mmd`만 고쳐 다시 변환한다.
4. 문서에는 삽입 위치에 빨간 굵은 글씨로 `[도식 삽입: 파일명] 이 줄을 지우고 이미지를 넣어 주세요` 단락을 넣는다.
5. **업로드와 삽입은 사용자가 한다**(드라이브에 끌어 놓기 → 구글 문서 "삽입 → 이미지 → 드라이브"). Claude가 PNG를 업로드하면 base64를 옮겨 적어야 해서 도식당 30~80KB가 들므로 하지 않는다. 외부 변환 서비스 주소도 쓰지 않는다(기획 내용 외부 전송).
6. 사용자가 삽입을 마치면 `check_format.py`로 남은 `[도식 삽입:` 표시가 없는지 확인한다.
7. 이미지 크기 조정은 사용자가 직접 한다.
8. **도식 데이터는 커밋하지 않는다.** `Docs/Portfolio/diagrams/`(`.mmd`·`.png`·작업용 설정)는 루트 `.gitignore`로 제외되어 있다. 도식을 다른 위치에 만들지 않고, 커밋 파일 목록을 제안할 때도 넣지 않는다. 스킬 폴더의 `mermaid-config.json`·`puppeteer.json`은 도구 설정이라 커밋 대상이다.

## 6. 보정 스크립트가 처리하는 것 (`postfix.py`)
페이지 없음, 단락 간격 모드 `NEVER_COLLAPSE`(목록 항목 사이 간격 유지), 전체 글꼴, 문서 제목(TITLE), 제목 간격·다음 단락과 함께, 2단계 이하 목록 들여쓰기, 표 열 너비(2열 130/368pt, 그 외 전체 498pt 비례)·머리행 고정, 구분선 단락 분리(빈 줄 + 구분선), 표 뒤 빈 줄. **문서에 이미 같은 값이 들어간 스타일·표 요청은 출력에서 뺀다**(뺀 개수는 stderr). 그래서 보정을 다시 돌려도 바뀐 부분만 나온다. 추가 보정(`--extra-only`로 따로 낼 수 있음): 제목·장·절 제목 굵게(HTML 변환이 굵게 해제를 박아 둠), 모든 단계 목록 들여쓰기(단계마다 32.4pt)와 연속 단락 들여쓰기(바로 앞 항목의 글자 위치), 표 글자 크기·셀 단락 줄간격·간격·머리행·첫 열 굵게, 단락 간격, 마침표 분리.

## 7. 알려진 함정
- 새 문서 기본 단락 간격 모드는 `COLLAPSE_LISTS`라서 목록 항목 사이 간격이 첫 항목에만 남는다 → 보정 필수.
- 표 테두리는 셀마다 지정된다. 나중에 행·열을 추가하면 새 셀은 검정 기본 테두리가 붙을 수 있다고 보고에 적는다.
- 목록 단계를 바꿀 때는 `deleteParagraphBullets` → **들여쓰기 0으로 초기화** → 단계 수만큼 탭 삽입 → `createParagraphBullets` 순서로 한다. 들여쓰기를 초기화하지 않으면 기존 들여쓰기가 더해져 한 단계 더 깊어진다. 같은 길이로 바꾸는 편집(`, `→`,\u000b`, `\u000b`→`\n`)은 위치가 변하지 않아 한 묶음에 넣을 수 있다.
- `replaceAllText` 뒤에도 위치가 바뀔 수 있으니 위치 기반 요청 전에는 항상 다시 읽는다.
- 시험·임시 문서를 만들었으면 보고 때 알리고, 사용자가 원할 때만 휴지통으로 옮긴다.
