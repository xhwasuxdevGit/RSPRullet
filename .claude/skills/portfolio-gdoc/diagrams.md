# 도식 작업 절차 (portfolio-gdoc)

0번 브리핑 형식은 정제 단계에서 쓴다(장 구성 개선안이 있으면 같은 브리핑에 함께 넣는다). 1번부터는 브리핑이 승인된 뒤에만 진행한다.

0. **정제 브리핑의 도식 부분 (승인 전 도식 작성 금지)**
   ```text
   ## 정제 브리핑
   | 위치(장·절) | 도식이 필요한 이유 | 구성 내용(노드·흐름) | 도식 종류 |
   | 예: 2.1 라운드 진행 | 패배 시 재도전 분기가 글로는 따라가기 어려움 | 시작→1R→2R→3R→클리어, 각 라운드 패배→응급약 복용 | 흐름도(LR) |
   **대안 비교** 위치·구성·방식(이미지 도식 / 표 도식 / 텍스트 흐름 유지)에 대안이 있으면 장단점 표로 비교하고 권장안을 밝힌다. 대안이 없으면 "해당 없음: 이유".
   진행할까요?
   ```
   - 승인된 위치·구성대로만 만든다. 사용자가 빼거나 바꾼 항목은 반영하고 다시 묻지 않는다. 승인되지 않은 곳은 텍스트 흐름으로 둔다.
1. 머메이드 원문을 `Docs/Portfolio/diagrams/장-절_이름.mmd`로 쓴다.
   - 직선 흐름은 `flowchart LR`, 주고받는 순서는 `sequenceDiagram`(자기 동작은 `Note over`로 써야 글자가 세로선과 겹치지 않는다).
   - 분기·되돌아가기는 자기 반복 화살표 대신 별도 노드로 모은다(계단식 배치 방지).
2. 로컬에서 PNG로 변환한다(설치된 Chrome 사용, 브라우저 내려받기 없음):
   `npx -y @mermaid-js/mermaid-cli@11.4.2 -i X.mmd -o X.png -c <skill>/mermaid-config.json -p <skill>/puppeteer.json -b white -s 2 -w 1000`
   - `mermaid-config.json`에 문서 색과 Noto Sans KR이 들어 있다.
3. PNG를 Read로 열어 겹침·잘림·이상한 줄바꿈을 확인한다. 고칠 때는 `.mmd`만 고쳐 다시 변환한다.
4. **업로드·삽입·크기 조정은 사용자가 한다**(드라이브에 끌어 놓기 → 구글 문서 "삽입 → 이미지 → 드라이브"). 삽입 위치에는 원고 업로드 때 넣은 `[도식 삽입: 파일명]` 표시 단락(SKILL.md 4장 2단계)이 있다. Claude가 PNG를 올리면 base64를 옮겨 적어 도식당 30~80KB가 든다. 외부 변환 서비스도 쓰지 않는다(기획 내용 외부 전송).
5. 사용자가 삽입을 마치면 `check_format.py`로 `[도식 삽입:` 표시가 남지 않았는지 확인한다.
6. **도식 데이터는 커밋하지 않는다.** `Docs/Portfolio/diagrams/`는 루트 `.gitignore`로 제외되어 있다. 다른 위치에 만들지 않고 커밋 목록에도 넣지 않는다. 스킬 폴더의 `mermaid-config.json`·`puppeteer.json`은 커밋 대상이다.
